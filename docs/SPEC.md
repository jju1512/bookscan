# 북스캔 웹앱 개발 명세서

2026년 11월 25일 · 익주 (원문 그대로 보관. 이 파일이 요구사항의 기준이다)

## 1. 개요

안드로이드 크롬에서 책을 펼쳐 두고 페이지만 넘기면 자동으로 촬영되는 북스캔 웹앱을 만든다. 서버 없이 GitHub Pages에 정적 사이트로 배포하고, 이미지는 사용자 기기의 브라우저 저장소에 저장한다. 사용자가 원하면 구글 드라이브에도 올린다.

스캔할 때는 AI 없이 오픈소스 영상 처리만 쓴다. 스캔이 끝나면 후처리(자르기, 손가락 지우기, 평평하게 펴기, OCR, PDF)를 실행한다.

### 이 문서를 받는 개발자에게

- 이 문서가 요구사항의 기준이다. 문서와 다르게 구현해야 할 이유가 생기면, 구현하기 전에 사용자에게 먼저 묻는다.
- 5장의 Phase 순서대로 진행한다. Phase마다 완료 조건을 채우면 사용자에게 실기기 테스트를 요청하고, 확인을 받은 뒤 다음 Phase로 넘어간다.
- 자동 촬영의 기준값과 후처리 품질은 실제 책을 찍어 봐야만 검증된다. 튜닝 파라미터는 config 한 곳에 모으고, 화면에서 바로 바꿔 볼 수 있는 디버그 패널을 만든다.
- 범위 밖: iOS와 사파리, 로그인·계정 시스템, 서버와 DB, 데스크톱 카메라 촬영. PC 크롬은 후처리와 열람 용도로만 지원한다.

## 2. 확정된 결정사항과 제약

아래 항목은 사용자와 합의된 내용이다. 바꿔야 한다면 먼저 사용자에게 확인한다.

| 항목 | 결정 |
|---|---|
| 대상 환경 | 안드로이드 크롬 최신 안정 버전. PC 크롬은 후처리와 열람만 |
| 형태 | 정적 웹앱 + PWA (홈 화면 설치, 오프라인 동작) |
| 배포 | GitHub Pages. GitHub Actions로 빌드와 배포 자동화 |
| 서버·DB | 없음. 모든 처리는 브라우저 안에서 한다 |
| 로컬 저장 | 메타데이터는 IndexedDB, 이미지 파일은 OPFS. localStorage에는 이미지를 저장하지 않는다 (작은 설정값만 허용) |
| 클라우드 | 선택적 구글 드라이브 연동. 권한 범위는 drive.file 하나만 쓴다 |
| 스캔 단계 | AI 모델 사용 금지. OpenCV.js 등 오픈소스 영상 처리만 쓴다 |
| 후처리 단계 | 스캔이 끝난 뒤 실행한다. 오픈소스 방식으로 먼저 완성하고, 결과가 부족한 단계만 AI 모델(ONNX Runtime Web)로 교체한다 |
| 촬영 환경 | 휴대폰을 거치대에 고정한 상태를 기본 전제로 한다 |
| 촬영 단위 | 기본은 펼친 양쪽 페이지를 한 장으로 찍는다. 좌우 분할은 후처리에서 한다 |
| 개인정보 | 이미지는 사용자 기기와 사용자 본인의 드라이브 외에는 어디에도 보내지 않는다. 분석·추적 도구는 넣지 않는다 |

### 플랫폼 제약 (설계에 반드시 반영)

- 카메라(getUserMedia)는 HTTPS에서만 동작한다. GitHub Pages는 HTTPS라서 문제없고, 로컬 개발은 localhost나 HTTPS 개발 서버를 쓴다.
- GitHub Pages는 COOP/COEP 헤더를 설정할 수 없다. 그래서 SharedArrayBuffer와 멀티스레드 WASM을 기본으로 쓸 수 없으므로, 단일 스레드 WASM을 기준으로 설계한다. 멀티스레드가 꼭 필요하면 coi-serviceworker 방식을 검토하되, 구글 로그인 팝업과 충돌하지 않는지 먼저 확인한다.
- 웹 페이지는 안드로이드 볼륨 키 입력을 받을 수 없다. 수동 촬영은 화면 탭으로 하고, 블루투스 키보드·리모컨의 Enter/Space 키 지원은 선택 사항으로 둔다.
- 탭이 닫히거나 백그라운드로 가면 처리가 멈춘다. 업로드와 후처리는 모두 중단되었다가 이어서 할 수 있게 만든다 (4장).

## 3. 기술 스택과 아키텍처

무거운 영상 처리는 모두 Web Worker에서 돌린다. 메인 스레드는 화면과 카메라 미리보기만 담당한다.

| 영역 | 선택 | 비고 |
|---|---|---|
| 언어·빌드 | TypeScript + Vite | UI 프레임워크는 개발자 재량. 번들 크기가 작은 쪽(없음 또는 Preact·Svelte)을 권장 |
| 카메라 | getUserMedia + ImageCapture.takePhoto() | takePhoto가 느리거나 미리보기를 끊으면 최대 해상도 스트림 프레임 캡처로 대체 |
| 영상 처리 | OpenCV.js (WASM) | Worker에서 실행. Mat은 반드시 delete()해서 메모리 누수를 막는다 |
| 화면 꺼짐 방지 | Screen Wake Lock API | 촬영 화면에서만 켠다 |
| 저장 | IndexedDB(idb 래퍼) + OPFS | 4장 참고 |
| ZIP | fflate | 내보내기·가져오기 |
| PDF | pdf-lib (+ fontkit) | 검색 가능한 PDF용 한글 폰트 서브셋 임베드 |
| OCR | Tesseract.js (kor+eng) | 정확도가 부족하면 PaddleOCR 한국어 모델(ONNX)로 교체 |
| AI 실행 | ONNX Runtime Web | WebGPU 우선, 안 되면 WASM. 후처리에서만 사용 |
| 구글 | Google Identity Services(토큰 모델) + Drive REST API v3 | gapi 클라이언트 없이 fetch로 직접 호출 |
| PWA | 서비스 워커 (vite-plugin-pwa 등) | 앱 셸과 OpenCV.js는 설치 시 캐시. AI 모델은 처음 쓸 때 내려받음 |

### 폴더 구조 (권장)

```
src/
  app/        화면, 라우팅, 온보딩
  camera/     카메라 열기, 미리보기, 고해상도 촬영, 플래시
  capture/    자동 촬영 상태 머신, 프레임 분석 worker
  storage/    IndexedDB·OPFS 저장소, 작업 상태, 복구
  sync/       구글 로그인, 드라이브 업로드 대기열
  process/    후처리 파이프라인 worker
    crop/  finger/  dewarp/  enhance/  ocr/
  export/     PDF, ZIP 내보내기·가져오기
  config/     튜닝 파라미터 (한 곳에만)
  debug/      디버그 패널, 세션 녹화, 로그
tests/
  fixtures/   후처리용 샘플 이미지, 자동 촬영용 녹화 영상
```

### 데이터 흐름

1. 카메라 미리보기 프레임을 축소해서 capture worker로 보낸다. 상태 머신이 촬영 시점을 정한다 (6장).
2. 고해상도로 촬영하고, 원본을 곧바로 OPFS에 쓴 뒤 IndexedDB에 기록한다. 기록이 끝난 뒤에만 "촬영됨" 피드백을 준다.
3. 드라이브를 연동했다면 업로드 대기열이 뒤에서 원본을 올린다 (7장). 촬영은 업로드를 기다리지 않는다.
4. 사용자가 스캔을 끝내면 process worker가 페이지를 하나씩 후처리하고, 단계별 결과를 OPFS에 저장한다 (8장).
5. 내보내기로 검색 가능한 PDF나 ZIP을 만들고, 연동 중이면 드라이브에도 올린다.

## 4. 데이터 모델과 저장 규칙

목표는 두 가지다. 새로고침하거나 탭을 닫거나 폰을 꺼도 이미 찍은 페이지는 잃어버리지 않고, 모든 작업은 중단된 지점부터 이어서 한다.

### 데이터 모델 (IndexedDB)

촬영 한 번(Capture)이 후처리에서 좌우 두 페이지(Page)로 나뉜다. 그래서 둘을 따로 둔다.

```ts
type StepState = 'pending' | 'running' | 'done' | 'failed' | 'skipped';

interface Book {
  id: string; title: string; createdAt: number; updatedAt: number;
  captureMode: 'spread' | 'single';      // 양쪽 펼침 / 한 페이지
  driveFolderId?: string;
  scanState: 'scanning' | 'finished';
}

interface Capture {                       // 원본 촬영 1회
  id: string; bookId: string; seq: number; // 촬영 순서
  capturedAt: number;
  file: string;                            // OPFS 경로 (원본 JPEG)
  width: number; height: number; bytes: number;
  sharpness: number;                       // 촬영 시 선명도 점수
  thumb: string;                           // 썸네일 OPFS 경로
  upload: { state: StepState; driveFileId?: string; attempts: number; lastError?: string };
  deleted?: boolean;
}

interface Page {                          // 후처리 결과 1페이지
  id: string; bookId: string; captureId: string;
  side: 'left' | 'right' | 'single'; order: number;
  steps: { crop: StepState; finger: StepState; dewarp: StepState; enhance: StepState; ocr: StepState };
  files: { crop?: string; finger?: string; dewarp?: string; enhance?: string }; // OPFS 경로
  ocr?: { text: string; words: { t: string; x: number; y: number; w: number; h: number }[] };
  manual?: { corners?: number[]; splitX?: number };  // 수동 보정값
}
```

OPFS 경로는 `books/<bookId>/original/<seq>.jpg`, `books/<bookId>/pages/<pageId>/<step>.jpg` 형태로 한다.

### 저장 규칙 (필수)

1. 촬영하면 즉시 한 장씩 저장한다. OPFS에 파일을 쓰고 IndexedDB 트랜잭션이 커밋된 뒤에만 촬영 완료 피드백을 준다. 메모리에 모아 두었다가 한꺼번에 저장하지 않는다.
2. 업로드 상태와 후처리 단계별 상태는 모두 IndexedDB에 기록한다. 앱이 시작되면 running 상태로 남은 작업을 pending으로 되돌리고, 남은 작업부터 이어서 한다.
3. 저장이나 업로드가 끝나지 않은 작업이 있으면 페이지를 떠날 때 beforeunload 경고를 띄운다.
4. 첫 촬영 전에 navigator.storage.persist()를 요청한다. 거부되면 "공간이 부족하면 브라우저가 데이터를 지울 수 있음" 안내를 표시한다.
5. 시크릿 모드나 저장 불가 상태가 감지되면 "탭을 닫으면 사라집니다" 경고 배너를 띄운다.
6. navigator.storage.estimate()로 남은 용량을 표시한다. 여유가 부족하면 촬영 전에 경고하고 내보내기를 안내한다.
7. 원본은 사용자가 직접 지우기 전까지 삭제하지 않는다. 드라이브 업로드와 후처리가 모두 끝난 원본만 "로컬 정리" 옵션으로 지울 수 있고, 기본값은 꺼짐이다.
8. 책 단위 ZIP 내보내기·가져오기를 Phase 1부터 제공한다. ZIP에는 원본 이미지와 book.json(메타데이터)을 넣는다.

## 5. 개발 단계와 완료 조건

전체 예상 기간은 2~4개월이다. Phase마다 완료 조건을 채우면 사용자에게 실기기 테스트 체크리스트를 주고, 확인을 받은 뒤 다음으로 넘어간다. 완료 조건의 숫자는 출발점이며 사용자와 조정할 수 있다.

| Phase | 내용 | 예상 기간 | 완료 조건 |
|---|---|---|---|
| 0. 기반 | Vite+TS 프로젝트, GitHub Actions로 Pages 자동 배포, PWA 매니페스트와 서비스 워커, 카메라 권한 화면, 디버그 패널 틀 | 1~2일 | 휴대폰 크롬으로 Pages 주소에 들어가 홈 화면에 설치하고, 후면 카메라 미리보기가 보인다 |
| 1. 자동 촬영 | 책 만들기, 촬영 화면, 자동 촬영 상태 머신(6장), 탭 수동 촬영, 페이지 목록·미리보기·삭제·재촬영·순서 변경, 저장 규칙(4장), ZIP 내보내기·가져오기 | 2~3주 | 거치대에 고정하고 실제 책 50페이지를 연속으로 넘겼을 때 누락 1장 이하, 중복 1장 이하, 흔들린 사진 0장. 촬영 중에 새로고침해도 촬영본이 모두 남는다 |
| 2. 드라이브 연동 | 온보딩 연동 질문, 구글 로그인, 폴더 생성, 업로드 대기열, 재시도, 토큰 만료 처리, 다른 기기에서 불러오기(7장) | 1~2주 | 비행기 모드로 촬영 후 온라인이 되면 자동 업로드된다. 1시간 넘게 촬영해도 누락이 없다. PC에서 같은 책을 불러올 수 있다 |
| 3. 후처리 1차 (오픈소스) | 자르기·분할, 손가락 지우기, 펴기, 화질 보정, OCR, 검색 가능한 PDF, 수동 보정 UI, 전후 비교 화면(8장) | 5~8주 | 300페이지 책 한 권을 휴대폰에서 중간에 멈추지 않고 끝까지 처리한다. 중간에 새로고침해도 이어서 처리된다. PDF에서 한글 검색이 된다 |
| 4. 후처리 2차 (AI 교체) | 3단계 결과를 사용자가 평가한 뒤, 부족한 단계만 AI 모델로 교체. 모델 다운로드·캐시, 방식 선택 설정 | 3~6주 (선택) | 같은 샘플 세트에서 오픈소스 방식보다 나은 결과를 사용자가 확인한다 |
| 5. 마무리 | 성능 최적화, 오류 처리, README, 라이선스 정리, 릴리스 | 1~2주 | 9장의 비기능 요구사항을 모두 채운다 |

## 6. 자동 촬영 상세 (Phase 1)

화면이 크게 움직이다가(페이지 넘김) 다시 멈추면, 직전 촬영과 다른 장면인지 확인하고 촬영한다. 이 단계에서는 AI를 쓰지 않고, OpenCV.js나 Canvas 연산만 쓴다.

### 프레임 분석 (capture worker)

1. 미리보기에서 초당 약 12프레임을 가져와 가로 320px로 줄이고, 흑백으로 바꾼 뒤 가우시안 블러를 적용한다. createImageBitmap과 OffscreenCanvas를 쓴다.
2. 움직임 motion: 직전 분석 프레임과 비교해 밝기 차이가 PIXEL_DIFF보다 큰 픽셀의 비율.
3. 변화량 change: 마지막 촬영 순간의 축소 프레임(기준 프레임)과 비교한 같은 비율. 새 페이지인지 판단하는 데 쓴다.
4. 선명도 sharpness: 라플라시안 분산. 장면마다 절대값이 다르므로 최근 촬영들의 중앙값과 비교한 상대값으로 판단한다.

### 상태 머신

| 상태 | 의미 | 다음 상태로 가는 조건 |
|---|---|---|
| WAIT_STABLE | 시작 직후나 흐린 사진으로 촬영을 취소한 뒤. 안정되기를 기다린다 | motion < STILL 상태가 STABLE_MS 동안 이어지면 CHECK |
| CHECK | 촬영해도 되는지 검사한다 | 선명도 미달 → WAIT_STABLE. 첫 장이거나 change ≥ CHANGE_MIN → CAPTURE. 직전 촬영과 같은 장면 → 촬영하지 않고 ARMED |
| CAPTURE | 고해상도로 촬영하고 저장한다. 기준 프레임을 갱신한다 | 저장이 끝나면 ARMED |
| ARMED | 다음 페이지 넘김을 기다린다 | motion > MOVE 상태가 MOVE_MS 이상 이어지면 TURNING |
| TURNING | 페이지를 넘기는 중이다 | motion < STILL 상태가 STABLE_MS 동안 이어지고 마지막 촬영에서 MIN_INTERVAL_MS가 지났으면 CHECK |
| PAUSED | 사용자가 일시정지했거나 탭이 숨겨졌다 | 재개하면 WAIT_STABLE |

수동 촬영(화면 탭)은 어느 상태에서나 즉시 CAPTURE를 실행하고 기준 프레임을 갱신한다. 상태 머신은 카메라와 분리된 순수 함수로 만든다. 입력은 (시각, motion, change, sharpness)이고 출력은 (다음 상태, 촬영 여부)다. 그래야 단위 테스트와 녹화 영상 재생 테스트가 가능하다.

### 초기 파라미터 (config에 두고 디버그 패널에서 조정)

| 이름 | 초기값 | 의미 |
|---|---|---|
| ANALYSIS_WIDTH | 320 px | 분석용 축소 폭 |
| ANALYSIS_FPS | 12 | 초당 분석 횟수 |
| PIXEL_DIFF | 25 (0~255) | 바뀐 픽셀로 볼 밝기 차이 |
| STILL | 0.5% | 이보다 적게 바뀌면 멈춘 것 |
| MOVE | 5% | 이보다 많이 바뀌면 움직이는 것 |
| MOVE_MS | 150 ms | 페이지 넘김으로 인정할 최소 움직임 시간 |
| STABLE_MS | 400 ms | 멈춤으로 인정할 시간 |
| CHANGE_MIN | 8% | 직전 촬영 대비 이 이상 달라야 새 페이지 |
| SHARP_RATIO | 0.8 | 최근 촬영 선명도 중앙값의 이 배수 이상이어야 통과 |
| MIN_INTERVAL_MS | 800 ms | 연속 촬영 사이 최소 간격 |

### 카메라와 촬영

- 후면 카메라(facingMode: environment)를 가능한 최대 해상도로 요청하고, 실제로 받은 해상도를 디버그 패널에 표시한다.
- ImageCapture.takePhoto()를 우선 쓴다. 촬영 지연이 1초를 넘거나 미리보기가 끊기면, 최대 해상도 스트림의 프레임을 캡처하는 방식으로 바꾼다. 두 방식 모두 구현하고 설정에서 고를 수 있게 한다.
- 플래시(torch)는 기기가 지원할 때만 켜고 끌 수 있게 한다.
- 촬영 피드백은 짧은 셔터음(WebAudio), 진동(navigator.vibrate), 화면 테두리 깜박임, 페이지 카운터로 준다.
- visibilitychange로 탭이 숨겨지면 카메라와 Wake Lock을 해제하고 PAUSED로 간다. 돌아오면 다시 연다.
- 촬영 화면에 책을 맞추기 위한 가이드 틀과, 현재 상태(대기 / 넘김 감지 / 촬영)를 표시한다.

### 디버그 패널과 튜닝 도구

- motion, change, sharpness를 실시간 그래프로 보여 주고, 현재 상태와 상태 전환 로그를 표시한다.
- 파라미터를 화면에서 바꾸고 저장할 수 있게 한다.
- 세션 녹화: 디버그 모드에서는 미리보기를 MediaRecorder로 녹화해 내보낼 수 있게 한다. 같은 영상을 입력으로 상태 머신을 돌려, 파라미터를 바꿨을 때 촬영 시점이 어떻게 달라지는지 PC에서도 비교할 수 있게 한다. 실제 책으로 매번 다시 찍지 않고도 튜닝할 수 있어야 한다.

## 7. 구글 드라이브 연동 상세 (Phase 2)

드라이브는 백업과 기기 간 이동에 쓰고, 작업은 항상 로컬 사본으로 한다. 드라이브 상태가 어떻든 촬영을 막는 일은 없어야 한다.

### 흐름

1. 처음 접속하면 온보딩에서 "구글 드라이브에 백업할까요?"를 묻는다. 버튼은 [연동하기] [나중에]이고, 설정에서 언제든 바꿀 수 있다.
2. 연동하면 Google Identity Services 토큰 클라이언트로 로그인한다. 권한 범위는 https://www.googleapis.com/auth/drive.file 하나만 요청한다.
3. 드라이브에 BookScan/ 폴더를 만들고, 책마다 하위 폴더를 만든다.
4. 촬영된 원본은 업로드 대기열을 통해 뒤에서 올라간다. 후처리가 끝나면 PDF와 book.json도 올린다.

### 드라이브 폴더 구조

```
내 드라이브/BookScan/
  <책 제목>_<YYYYMMDD>/
    original/0001.jpg, 0002.jpg ...
    book.json      메타데이터 (다른 기기에서 복원할 때 사용)
    <책 제목>.pdf  후처리 후 최종본
```

### 업로드 대기열

- Capture.upload.state를 기준으로 동작하며, 동시에 2개까지 올린다.
- 실패하면 대기 시간을 2초, 4초, 8초로 늘려가며 재시도하고, 최대 간격은 5분이다. attempts와 lastError를 기록한다.
- online·offline 이벤트에 맞춰 멈추고 다시 시작한다.
- 5MB 이하 파일은 multipart 업로드, 그보다 큰 파일(PDF 등)은 resumable 업로드를 쓴다.
- 같은 파일이 두 번 올라가지 않도록, 업로드가 성공하면 driveFileId를 저장한다. 재시도 전에는 파일 이름으로 이미 올라간 파일이 있는지 확인한다.
- 화면에 "업로드 대기 N장"과 실패 건수를 표시한다.

### 로그인 만료 처리

- 서버가 없으므로 리프레시 토큰은 없고, 액세스 토큰은 약 1시간 뒤 만료된다.
- 토큰은 메모리에만 보관한다. localStorage나 IndexedDB에 저장하지 않는다.
- 401 응답을 받으면 대기열을 멈추고, 팝업 없는 재발급(prompt: '')을 시도한다. 실패하면 상단에 "드라이브 다시 연결" 버튼을 띄운다. 브라우저는 사용자가 직접 누른 경우에만 팝업을 열어 주기 때문이다.
- 만료된 동안 업로드는 대기 상태로 남고 촬영은 계속된다.

### 다른 기기에서 불러오기

- 같은 구글 계정으로 연동하면 BookScan/ 아래 book.json을 찾아 책 목록을 보여 준다. 사용자가 고른 책의 원본을 로컬로 내려받는다.
- drive.file 범위에서는 이 앱(같은 OAuth 클라이언트)이 만든 파일만 보인다. 사용자가 드라이브에 직접 올린 파일은 보이지 않는다는 점을 화면에 안내한다.
- 주된 용도는 휴대폰으로 촬영하고 PC 크롬에서 후처리하는 것이다.

연동 해제: 토큰을 폐기(google.accounts.oauth2.revoke)하고 대기열을 멈춘다. 로컬 데이터와 드라이브에 올라간 파일은 그대로 둔다.

설정값: OAuth 클라이언트 ID는 빌드 시 환경변수로 주입한다(VITE_GOOGLE_CLIENT_ID). 클라이언트 시크릿은 쓰지 않는다. 공개 배포를 하기 전에 OAuth 동의 화면의 게시 상태와 검증이 필요한지 사용자와 함께 확인한다.

## 8. 후처리 파이프라인 상세 (Phase 3·4)

스캔이 끝난 뒤 책 단위로 실행하고, 페이지를 하나씩 순서대로 처리한다. 단계 순서는 자르기·분할 → 손가락 지우기 → 펴기 → 화질 보정 → OCR → PDF이다.

### 공통 규칙

- 후처리는 process worker 하나에서 한 번에 한 페이지씩 실행한다. 브라우저 탭의 메모리가 부족해 탭이 죽는 것을 막기 위해서다.
- 처리할 때 이미지 긴 변은 최대 3000px로 줄여서 쓴다. 이 값은 설정으로 바꿀 수 있게 한다.
- 단계가 끝날 때마다 결과를 OPFS에 저장하고 Page.steps를 갱신한다. 중단되면 끝나지 않은 단계부터 이어서 한다.
- 모든 단계는 같은 인터페이스로 만든다: `run(input: ImageBitmap | Blob, meta) => Promise<{ image, meta }>`. 오픈소스 구현과 AI 구현을 서로 바꿔 끼울 수 있어야 한다.
- 단계마다 켜고 끌 수 있고, 페이지별로 특정 단계를 건너뛸 수 있다. 전후 비교 화면(원본과 결과를 나란히 보기)에서 결과가 나쁜 페이지만 다시 처리할 수 있게 한다.
- 후처리는 화면이 켜져 있을 때만 진행된다. 처리 중에는 Wake Lock을 켜고 진행률과 남은 시간을 표시한다.

### 단계별 구현

| 단계 | 1차: 오픈소스 (Phase 3) | 2차: AI 교체안 (Phase 4) | 실패하면 |
|---|---|---|---|
| 자르기·분할 | OpenCV로 가장자리를 검출해 책 외곽의 가장 큰 사각형을 찾고 원근을 보정한다. 가운데 영역에서 세로 방향으로 가장 어두운 선(책등 그림자)을 찾아 좌우로 나눈다 | 보통 필요 없음 | 원본을 유지하고 수동 보정 UI를 띄운다 (꼭짓점 4개와 분할선 드래그) |
| 손가락 지우기 | 페이지 가장자리 띠에서 YCrCb 피부색으로 손가락을 검출하고 형태 필터로 다듬어 마스크를 만든다. 여백이면 종이 배경색으로 채우고, 그 밖은 cv.inpaint(Telea)로 메운다 | MediaPipe Hand Landmarker로 손 영역을 찾고, LaMa 인페인팅(ONNX)으로 채운다 | 본문 글자와 겹치면 지우지 않고 표시만 한다 |
| 펴기 | page-dewarp 방식을 이식한다. 글자 줄을 검출해 페이지를 3차 곡면으로 모델링하고, 최적화한 뒤 리매핑한다 | UVDoc·DocTr 같은 문서 펴기 모델을 ONNX로 변환해 실행한다. 사용 전에 라이선스를 확인한다 | 글자 줄이 적은 페이지(그림·표)는 건너뛰고 자른 이미지를 쓴다 |
| 화질 보정 | 배경을 흰색으로 맞추고 대비를 조정한다. 선택 옵션으로 적응형 임계값 흑백 변환을 둔다 | 필요 없음 | 이전 단계 결과를 쓴다 |
| OCR | Tesseract.js(kor+eng). 페이지 텍스트와 단어별 좌표를 저장한다 | PaddleOCR 한국어 모델(ONNX) | 텍스트 없이 PDF를 만든다 |
| PDF | pdf-lib로 이미지와 투명 텍스트 레이어를 넣어 검색 가능한 PDF를 만든다. 한글 폰트는 필요한 글자만 서브셋해 임베드한다 | 해당 없음 | 이미지만 들어간 PDF를 만든다 |

손가락이 글자를 덮고 있으면 어느 방식으로도 가려진 글자는 복원할 수 없다. 그런 페이지는 목록에 표시해서 사용자가 다시 찍을 수 있게 한다.

### AI 모델 배포 (Phase 4)

- 모델은 앱에 포함하지 않는다. 처음 쓸 때 용량을 안내하고 동의를 받은 뒤 내려받아 Cache Storage나 OPFS에 보관한다.
- 호스팅은 같은 출처(GitHub Pages)를 기본으로 한다. Pages는 파일당 100MB 제한이 있다. 그보다 큰 모델은 CORS를 허용하는 호스팅(예: Hugging Face)을 검토한다. GitHub Releases는 브라우저에서 fetch로 받을 때 CORS가 되는지 먼저 확인한다.
- 모델을 쓰기 전에 모델별 라이선스를 THIRD_PARTY_LICENSES에 기록한다. 비상업 전용이나 GPL 계열이면 사용자에게 먼저 묻는다.

품질 비교 방법: tests/fixtures에 사용자가 찍은 샘플 30장 내외를 둔다. 두껍게 휘어진 페이지, 손가락이 나온 페이지, 그림이 많은 페이지를 포함한다. 구현을 바꿀 때마다 같은 세트의 단계별 결과를 한 화면에 모아 보는 비교 페이지(/debug/compare)를 만든다.

## 9. 비기능 요구사항, 테스트, 준비 사항

### 비기능 요구사항

- 오프라인: 앱 셸과 OpenCV.js를 서비스 워커로 캐시해서, 촬영과 로컬 저장이 네트워크 없이 동작하게 한다.
- 성능: 프레임 분석 때문에 미리보기가 끊기지 않게 한다. 촬영부터 저장 완료까지 1초 이내를 목표로 한다.
- 안정성: 어떤 오류가 나도 이미 저장된 촬영본은 손상되지 않아야 한다. 오류는 디버그 로그에 남기고 내보낼 수 있게 한다.
- 화면: 세로 화면 기준으로 만들고, 촬영 화면은 가로 화면도 지원한다. 글자와 버튼은 거치대에 올린 폰을 팔 길이에서도 볼 수 있는 크기로 한다.
- 라이선스: 사용한 모든 라이브러리와 모델을 THIRD_PARTY_LICENSES에 정리한다.
- 문서: README에 사용법, 로컬 개발 방법, 배포 방법, 구글 설정 방법을 적는다.

### 테스트

- 상태 머신 단위 테스트: 가짜 motion·change 시퀀스로 누락, 중복, 손만 움직인 경우, 흔들림을 검증한다.
- 녹화 영상 재생 테스트: tests/fixtures의 실제 페이지 넘김 영상으로 촬영 시점과 횟수를 확인한다.
- 저장 내구성 테스트: 촬영·업로드·후처리 도중에 새로고침했을 때 데이터가 남고 작업이 이어지는지 확인한다.
- 후처리 회귀 테스트: 샘플 세트의 단계별 결과 이미지를 저장해 이전 결과와 비교한다.
- 실기기 테스트는 사용자가 한다. Phase마다 확인할 항목을 체크리스트로 전달한다.

- [ ] 안드로이드 폰, 폰 거치대, 두께와 종이가 다른 테스트용 책 3권 이상 (Phase 1)
